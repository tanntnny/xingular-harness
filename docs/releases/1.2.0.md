# Xingular Harness 1.2.0

This release builds on the published 1.1.1 line.

## Compatibility note

The filesystem root cannot be used as an active workspace, because that would make the boundary
meaningless. The workspace boundary is intentionally stricter: model-controlled writes outside the active project,
including writes to temporary directories, require a one-call approval unless the eligible Full
Permission switch is explicitly enabled. Remembered per-tool grants do not cover them; unattended
runs cannot request approval. The Full Permission switch remains off by default. A workspace with
an external hard-link alias blocks default-scope Bash until the alias is removed or the file is
replaced with a copy. Native writes use atomic replacement and preserve ordinary file mode where
possible; ACLs and extended attributes are not guaranteed to survive replacement. On macOS, the
sandbox also blocks workspace-local hard-link creation.

## Workspace write boundary

Model-controlled file writes and Bash are scoped to the active project workspace by default. Native
write/edit operations revalidate the target and atomically replace the directory entry under an
OS-enforced write scope, so an in-workspace hard link does not modify an outside alias. Default Bash
scans for external hard links and runs in an OS sandbox that prevents cross-boundary hard-link
creation; unavailable or incomplete enforcement fails closed. Reads remain unchanged. Explicit
outside Bash writes require pre-execution one-call approval and run exactly once (`workspaceWriteScope:
'outside'`; in the terminal composer, `!outside <command>`). The approval shows the complete quoted
command in scrollable details; if the terminal is too small to show both details and choices, the
request is denied. Command output cannot trigger approval or automatic retry. Runs record their
resolved `workspaceRoot`; older run records remain readable.
Protection from a separate same-user process outside Harness is not provided.

## Planning and run continuity

Plan mode now requires evidence-grounded repository research and can delegate bounded read-only investigations to eligible research profiles. After compaction, active runs rehydrate the latest checklist and plan instructions. The terminal keeps the latest subagent status visible until its next run.

## Terminal commands and annotations

Plugin-owned terminal commands use `/<owner-prefix>:<command>`, while Harness-owned routes such as `/doctor`, `/worktree`, `/trajectory`, `/subagents`, and `/agents` are first-class core commands. Prior command forms remain hidden compatibility aliases for one release; migrate scripts and keybindings to the canonical names.

The annotation inspector now supports content in open shadow roots, including composed selections and targets. Closed shadow roots and frames remain unsupported, and existing document-only annotations retain their behavior.

## Terminal interaction

`/session` without a path now opens a searchable saved-session picker. Composer history includes user prompts, Bash commands and executed slash commands; browsing temporarily replaces the draft and restores its cursor, mode and attachments when it returns. Compact question docks now size each tab independently, keep nested sketches scrollable, and preserve page-footer hints at narrow widths.

## Performance evidence

Adds reproducible PTY and session-runtime profiling and publishes the [EXP-0003 report](../experiments/EXP-0003-performance-audit/results.md). That report is a 1.1.1 baseline captured from a dirty worktree, not a clean 1.2.0 benchmark; it also records a failed narrow-width `/settings` footer check and other measurement limits.

Node 22.19 or later is required. Building or running the standalone terminal also requires Bun 1.3.14 or later. See the project license and notices for third-party terms.
