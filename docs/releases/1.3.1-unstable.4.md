# Xingular Harness 1.3.1-unstable.4

Unstable preview of the current Harness work. Install with `npm install @xingular/harness@unstable`.

- Continue a terminal session from a phone or iPad with `/remote-control` (alias `/rc`), without a
  cloud relay (ADR-0056, [page 15](../architecture/15-remote-control.md)). The harness serves a small
  phone page on the computer's Tailscale address, or its private Wi-Fi address, and the terminal
  shows a half-block QR code for a one-device pairing link. A paired phone sends messages, watches
  the reply stream, stops it, and answers approvals and questions through the same `Terminals` and
  controller methods the terminal uses. Bodies are sealed with NaCl `secretbox` and a replayed
  counter is refused; device keys live in memory only, and remote control ends with the session.
  `xagent --remote-control` (`--rc`) turns it on at start, `/rc off` stops it, and the status bar
  reads `rc` while it is on and `rc ●` while a device is connected. Terminal runs now also record
  streamed `message.delta` events. New dependencies: `tweetnacl`, `uqr`.
- Classify a plan reply instead of guessing at it, and repair one bad reply. An attended top-level
  plan run has one shared outcome: `plan_ready` for a complete `<proposed_plan>`, `blocked` when a
  required decision cannot be obtained, and `invalid` for missing, incomplete, conflicting or
  malformed blocks; only `plan_ready` offers a plan card and Implement (ADR-0055, ADR-0057,
  ADR-0058). An `invalid` reply gets one hidden format-repair turn in the same run, and a failed
  repair leaves the run completed with a warning instead of a plan choice. Clarification now goes
  through the blocking `ask_user` tool, so new final replies no longer use `<plan_clarification>` or
  free-text questions. Both the server and the terminal use the same classification rather than
  separate heuristics. The App's plan card has not adopted the classification yet.
- Report a live reply's heartbeat every 30 seconds, and end a reply that produces nothing but
  heartbeats for 15 minutes as `interrupted` with reason `stalled`, instead of showing a run that
  never settles (ADR-0054). A running tool gets 30 minutes, and an unanswered approval or question is
  never cut short. Before this, a terminal reply reported no heartbeat at all, so the run sweep
  waited the full 30-minute silence window and recorded `owner_gone` while the process was alive.
- Stop refusing repeated work (ADR-0053). A reply is no longer refused or ended for calling the same
  tool with the same arguments three times, for a Bash check that keeps failing, or for editing one
  path more than four times: those calls are ordinary work and the reply budget is the single bound.
  The 320-call/60-minute budget, its checkpoint handoff, slice continuation and the
  three-compaction thrash rule are unchanged, and the `stuck` checkpoint reason stays readable in
  existing runs.
- Answer what the latest request was made of with `/context`. The page has a Request tab (one row per
  contributor with its estimated tokens and share of the window, four-colour ownership bar with a
  free track and a compaction marker) and a Growth tab (how the window filled over the session).
  `space` folds a group, `enter` shows one row's text, `g` switches grouping between owner and kind,
  and `c` asks the session to compact. `terminal.context` serves it from `context.attribution`; the
  status band reads the same share, such as `18.3%/1M`.
- Render the `/btw` side answer as Markdown instead of plain text. Headings, emphasis, lists, quotes,
  links, tables and fenced code use the theme's markdown colours, a streaming answer re-renders in
  place, and terminal control sequences in model output are still removed.

## Upgrading

- Two new runtime dependencies arrive with remote control: `tweetnacl` and `uqr`.
- A plan reply that ends in `<plan_clarification>` or a free-text question is now `invalid` and gets
  the single repair turn; use `ask_user` for a decision the run needs before it can plan.
- The `stuck` checkpoint reason is no longer produced, but it stays readable in existing run records.
