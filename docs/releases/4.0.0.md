# Xingular Harness 4.0.0

This major release builds on the published 1.0.0 baseline. It extends Harness-owned terminal
surfaces and adds generic worktree and page-annotation capabilities; it also changes the built-in
terminal command namespace, documented below. Earlier published versions remain available.

## Included

- Managed Git worktrees for sessions and the terminal, with leases, guarded setup scripts, handoff,
  pruning, restoration, and bounded snapshots that preserve uncommitted work.
- Page annotations and queued notes, including capture, review, resolution, sharing, and delivery
  through Harness methods and terminal `/plugin:annotate` and `/plugin:notes` pages.
- A unified terminal resource browser with persistent full-screen sections for browser tabs,
  plugins, skills, connectors, variants, and other Harness resources.
- A full-screen `/plugin:trajectory` Runs/Events browser with searchable event details, selected-event
  JSON, and a responsive split-pane layout.
- Additional terminal controls for browser settings, plugin settings, and subagent activity.
- Updated architecture and parity documentation for Harness capabilities and their terminal and
  host surfaces.

## Installation and requirements

Use `npm install --global @xingular/harness@4.0.0`, then `xharness`. Node 22.19 or later is required.
The interactive terminal also requires Bun; release CI uses Node 22.19.0 and Bun 1.4.2. Browser
operation requires an installed compatible browser or a deliberately configured endpoint. Model
credentials are configured inside an isolated Harness account.

## Compatibility

The new server methods are additive, but the built-in terminal command namespace changes: use
`/plugin:doctor` and `/plugin:trajectory` in place of `/doctor` and `/trajectory`. New feature
commands are namespaced from their introduction. Update scripts and keybindings that invoke the old
commands. Existing session, variant, account, plugin, and browser contracts remain in place. Install
this exact version or use the `latest` tag; historical versions remain available.

## Verification scope

The Harness CI suite, standalone proof, App typecheck/tests/layer check/Rust tests, and App UI
consistency check must pass for the reviewed release candidate. The release tag workflow separately
builds and smoke-tests the exact tarball on its supported operating systems before publishing it
with npm provenance.
