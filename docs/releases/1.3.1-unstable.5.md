# Xingular Harness 1.3.1-unstable.5

Unstable preview of the current Harness work. Install with `npm install @xingular/harness@unstable`.

- Namespace plugin commands (ADR-0061). A plugin-owned extension command and a plugin-owned prompt
  template now share one owner namespace, `/<owner-prefix>:<name>`, and bare plugin aliases are
  gone. A package can name its root template with `harness.defaultPrompt`; owner and route
  collisions fail closed. Standalone templates, `/skill:<name>` and the core commands are
  unchanged, and structured sessions route through the same registry.
- Make an approval a control, never a typed permission (INV-GATE-9, ADR-0060). The compiled
  guidance tells the model to call the tool, and the Harness pauses that exact call in
  `waiting_for_approval`; Allow resumes it in the same turn and a denial returns a tool result on
  the still-running turn. No surface accepts a typed approval instead of a control, nothing outside
  the workspace changes before the click, and Full Permission remains the standing bypass.
- Record refusals and stop codes (ADR-0059). The gate and the work-slice bound emit `tool.refused`
  with a bounded reason and a code (`plan_mode`, `workspace`, `scope`, `policy`, `capability`,
  `approval_denied`, `unattended`, `work_slice`, `controller_unavailable`), `trajectory_search`
  reports `terminalReason` and `terminalCode`, and `/trajectory` shows both. Compaction events carry
  the token measurements that were available when they happened; older run records still read.
- Answer `/context` from one run view. The page gains a Run details tab fed by
  `context.runDetails`, listing the facts a run recorded (status, mode, model, effort, variant
  version, workspace, tools and more), with `null` where a record has no such fact.
- Keep a refused question answer in the terminal. A choice, note or typed answer the Harness would
  reject stays in the dock with an inline reason naming the question and the field, instead of
  closing the form and losing the draft.
- Scroll a `/btw` answer taller than its block: PageUp/PageDown reach the side-question dock while
  it is open and the wheel over the block browses it. When the answer fits, those keys scroll the
  transcript as before.
- Drop the context-use figure from the composer status line, so it no longer ends the token group
  with a reading such as `6.6%/?`. The project and branch, account, model and effort, and the
  input/cache hit rate/output tokens remain; the share of the window stays in the `/context` page
  header. Both the OpenTUI status bar and the exported `tui/status` band lose the reading.
- Define the interaction side of computer control, still host-owned (PAR-007). `computer/control.ts`
  is an unregistered adapter whose backend must revalidate session approval, window identity and run
  liveness at the point of effect; `computer/boundary.ts` builds the approval details for one action
  against one window; `computer/terminalCapture.ts` is the trusted host contract for a
  person-selected window with a fresh decision per capture. The Harness registers no computer tool
  and ships no backend, so the terminal has no computer screenshot or interaction surface; a host
  that cannot guarantee the contract must not supply one.

## Upgrading

- A bare plugin command such as `/xdiag` no longer resolves. Use the owner namespace,
  `/<owner-prefix>:<name>`; `xingular-devkit` 0.2.0 ships `harness.commandPrefix` `xdiag`.
- A typed "yes" is never an approval. Deny a call to end it; Allow resumes that same call.
- Run records gain refusal events, `terminalReason` and `terminalCode`. Older records remain
  readable and report `null` for a fact they did not record.

## Publication note

This preview was published with the test job removed and without waiting for the smoke job, by
request. The candidate pack, integrity check, preflight, provenance and registry verification in
the publish job still ran. The `check` job and the smoke gate are restored in the next commit.
