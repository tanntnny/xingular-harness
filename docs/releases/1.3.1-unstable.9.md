# Xingular Harness 1.3.1-unstable.9

Unstable preview of the current Harness work. Install with `npm install @xingular/harness@unstable`.

- A reply can no longer quietly stop with work open (ADR-0069, ADR-0071). In attended top-level runs,
  terminal included, a reply that ends while its todo list has open items is sent back to the model,
  naming the items, up to three times per reply and never after a nudge produced no work; such a reply
  settles `interrupted` with the stop codes `needs_person` or `unfinished`, never `completed`, with a
  checkpoint the harness writes from the todo list, files and checks. `checkpoint_write` is removed.
  The work-slice budget now covers the whole reply, so Pi's own continuations no longer reset it.
  A live terminal session keeps the code it started with, so restart it to get the gate.
- A completion check decides whether a reply may end (ADR-0071). When a reply that did work ends with
  its todo list closed or absent, the run's own model, at low effort and with a fresh context, judges
  the person's request against what the reply did: `done`, `continue` (the reply is sent back with the
  reason and next step) or `needs_person`. It shares the stop gate's cap of three nudges per reply and
  its no-progress rule, its request counts in the run's usage, and any failure leaves the reply as it
  was. `finish` is removed: a live run used it after 23 seconds to ask something the handoff already
  answered. `XINGULAR_STOP_GATE=off` and `XINGULAR_COMPLETION_CHECK=off` switch either layer off at
  launch.
- The model is told it has `edit` and `write`. Pi drops the definition's prompt line and guidelines for
  its edit and write tools and lists only tools that have one, so every terminal and headless run's
  system prompt named only `read` and `bash`; models edited files through shell scripts instead (one
  2-hour run: 156 script edits, 14 failed, no `edit` call). `createWorkspaceFileTools` now restores the
  prompt line and guidelines, for the terminal and the runner alike.
- A plan no longer leaks its tools into normal mode. A rebuild before Pi recorded the restored normal
  set (a new runtime, resume, switch, fork or tree navigation) replayed the plan set, so normal work
  ran without `edit`, `write`, browser and connected-app tools even though the model had planned to use
  them. The terminal now marks each plan request in the session and restores the normal set after any
  rebuild.
- Terminal replies continue across work slices (ADR-0070). A reply that reaches its 320-call or
  60-minute budget after doing work continues in place as the next slice, with a checkpoint and a
  notice, up to 8 slices, instead of waiting for "continue" and re-sending the whole context uncached.
  Fruitless, blocked, failed, aborted and plan slices still stop. `XINGULAR_WORK_SLICE` also accepts
  key=value pairs such as `maxToolCalls=15,maxSlices=3`.
- One copy of each credential: no more `invalid_grant` from terminals. A terminal kept the account's
  tokens in its own `auth.json` under its own lock while the host, its subagents and usage probes
  refreshed the same token in the Keychain, and `terminalEnd` copied the file back over whatever the
  Keychain held; OpenAI rotates refresh tokens, so whichever side refreshed second failed. A terminal
  now reads and refreshes through the host store (`accounts.credentials.*`, INV-ACC-5), holding its
  lock for the refresh, and folds in an `auth.json` left by an older terminal, newest token first.
- A stalled terminal reply is recorded as `stalled`. Pi's abort reports through `terminal.interrupt`
  like a person's Esc, which closed the run as `user_abort` before the reply settled as `stalled`; one
  silent 15-minute hang was recorded as the person's abort. The interrupt now carries the stall, and an
  interrupt also ends a settling reply's wait for its subagents.
- `spawn_subagent` returns the child's tools, and the read-only profiles say up front when a brief needs
  a tool they lack.
- Prompt: the role paragraph sets the scope of the work — the obvious adjacent step, what the work
  itself exposes, the check it needs, inside the working folder and away from what a person must decide
  (a deploy, a secret, remote data, money), without asking first inside those bounds — and the
  reporting guidance requires `## Beyond what you asked` and `## What would make this complete` when
  they apply (ADR-0068). The role budget rises from 1,500 to 2,200 characters and the reporting budget
  from 2,000 to 2,400. All of it is stable-prefix text, so the cached prefix changes once per session.

Published without the test suites, by request.
