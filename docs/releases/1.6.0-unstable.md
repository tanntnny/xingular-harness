# Xingular Harness 1.6.0-unstable

Unstable preview of the current Harness work. Install with `npm install @xingular/harness@unstable`.

- **Your own signed-in Brave profile (ADR-0082).** `/settings` → Browser now chooses the browser
  backend: the isolated Harness profile, or Brave through a paired unpacked extension that ships in
  the package. Pairing uses a one-time `port:code` over an authenticated loopback bridge; each site
  is allowed separately by exact origin in the extension popup; an in-page badge offers Pause and
  Stop. The agent gets the same `browser_*` tools and the same approval gate, snapshot refs
  included, and `browser_upload` stays WebKit-only. A disconnect refuses calls and never falls back
  to the isolated browser. New methods `browser.config`, `browser.configure` and
  `browser.extension.status|start|stop`; `browser.json` gains `backend`.
- **A reply that waits on children or on a flaky network no longer looks stalled (ADR-0078).** Each
  subagent the reply waits on gets its own stall clock, the parent's clock pauses while it only
  waits, and a transient model failure retries for about four minutes instead of fourteen seconds.
  The working row says what the reply is doing: waiting on children, running a long tool, waiting
  for the model, reconnecting, or making no progress.
- **A plan run may conclude that no plan is needed (ADR-0077).** A plan reply with no plan block
  ends as `no_plan` with no card, notice or repair turn. Only a block the model started and left
  incomplete is repaired, once, in the same run.
- **No work-slice budget by default (ADR-0081).** A reply is no longer ended at 320 tool calls or
  60 minutes and continued as a "next slice". `workSlice` on a run and `XINGULAR_WORK_SLICE` still
  set a budget, and the three-compaction guard stays.
- **Phase-led, flexible reporting (ADR-0079).** The `reporting` guidance is written for a reader
  picking up cold: verification that did not run says so, subagents get a concise caller-facing
  report contract, and a substantial report may use content-named headings. The duplicated
  progress-update line moved out of `reporting` and stays in `writing`.
- **The follow-up and steering queue has a page.** `/follow-up`, and clicking a `Steer:` or
  `Follow-up:` row, opens an editor for the queued messages with edit, send next, remove and
  return. An explicit stop now sends one unconsumed steering message before the follow-ups.
- **Question sketches use one 80-column canvas (ADR-0080).** The model draws on a fixed 80-column
  canvas and the terminal pads every valid sketch to it, with the frame inside the dock and
  horizontally pannable. Stored sketches and answer payloads are unchanged.
- **CamelCase names everywhere in the transcript.** The 1.5.1 candidate predated the last of this
  work, so this release carries the todo card, custom message types, a child's activity and the
  phone page using the same `TodoWrite`/`ComputerScreenshot` form.

Two prompt sections change (`reporting` and the work-slice wording), so the stable prefix misses the
provider cache once per existing session after the upgrade. The Brave backend is opt-in and off by
default; the isolated browser is unchanged.
